# 코딩테스트 패턴 카탈로그 생성 프롬프트 (v1)

이 프롬프트는 코딩테스트 **패턴 1개** (예: DP / 그래프 / 백트래킹 / 투포인터 / 슬라이딩윈도우 / 이분탐색 등)에 대해 **코딩테스트장에서 즉시 꺼내 쓰는 패턴 카탈로그**를 만들 때 쓴다.

오픽 단원 카탈로그(`agents/카탈로그_생성.md`)의 7섹션 골격을 코딩테스트 도메인으로 그대로 일반화했다. 시드(모범 형식) 산출물은 `카탈로그/비교_A.md`의 구조감을 따라간다. 단, **표현 자리 → 코드 스니펫 자리**로 바뀐다는 점만 다르다.

---

## 0. 시작 멘트 (사용자가 첫 발화로 패턴 명시)

사용자가 첫 메시지에 어떤 패턴인지 명시한다. 예시:
- "**DP 패턴**으로 진행해. 문제는 LeetCode 70/198/300/322/1143."
- "**그래프 BFS/DFS**, 백준 1260/2178/7569."
- "**백트래킹**, 프로그래머스 N-Queen 외 5개."

너의 첫 응답은 패턴·문제 확인 + 작업 계획 한 문단:

> "안녕, **{패턴}** 카탈로그 만들 거야. 입력은 {문제 N개}.
>
> 시드 카탈로그(`카탈로그/비교_A.md`)와 같은 7섹션 골격으로 만들 건데, 이 패턴만의 **코어 메커니즘**(예: DP = '이전 상태로 현재 만들기')이 뭔지 먼저 대표 문제 2~3개 + 레퍼런스 코드 정독해서 잡고 시작할게. 그게 안 잡히면 문제를 더 읽고."

---

## 1. 입력 자료

### 1-1. 패턴 대표 문제 (1순위, 필수)

사용자가 제공한 **5~10개** 문제. 각 문제마다 가능한 것:
- 문제 출처 (LeetCode 번호 / 백준 번호 / 프로그래머스 레벨)
- 문제 본문 (제약조건 + 입출력)
- 레퍼런스 코드 1~2개 (강의 / 에디토리얼 / 공식 해설)

**1순위 정독 대상**:
- 가장 기초 문제 (예: DP에서 Fibonacci, Climbing Stairs)
- 가장 빈출 변형 (예: DP에서 LIS, Coin Change)
- 여기에 **패턴 코어 동작 + 자주 빠지는 함정**이 다 들어있다.

### 1-2. 스타일 모범 (필수)

- `카탈로그/비교_A.md` — **형식·톤·인용 방식 그대로 따라라**. 7섹션 골격, 출처 표기, 표/매트릭스, 이모지 마커(🟢🟡🟠🔵🟣).
- 사용자 본인 노트가 있으면 흡수 (개인 함정 메모, 자주 까먹는 syntax 등).

### 1-3. 참고 (선택)

- 알고리즘 교재 / 강의 슬라이드 (있을 때만)
- 분석 트리 깊이는 줄이고, **코드 스니펫이 메인 자리**.

## 2. 절대 가드레일 (양보 불가)

오픽 카탈로그에서 7번 피드백으로 정착한 G1~G6을 코딩테스트로 매핑한 것. 사용자가 단계별 피드백 안 준다 → **너 혼자 지켜야 한다**.

### G1. 메커니즘 분석 < 코드 스니펫이 메인
- 카테고리 헤더 → **코드 스니펫 (3~15줄)** → 짧은 출처/메모.
- 시간복잡도·공간복잡도 분석은 **코드 옆 한 줄 메모**로만.
- 시험장에서 펼치면 **복붙 가능한 코드**가 먼저 보여야 한다. 분석 산문이 코드보다 길어지면 위반.

### G2. 추상 라벨 새로 만들지 마라 (정해진 패턴명만)
- 금지: "관찰형 DP / 인지형 DP", "트리거형 그래프", "선언형 백트래킹" 같은 새 분석가 라벨.
- 허용: **통용 명칭만** (Top-down / Bottom-up / 1D DP / 2D DP / 비트마스크 DP / BFS / DFS / 양방향 BFS / 0-1 BFS / 백트래킹 / 가지치기 / 이분탐색 / 매개변수 탐색 등).
- 라벨이 두 개 이상 새로 생기는 신호 → 라벨 빼고 코드만 나열.

### G3. 패턴 식별 시그널 박아라 (Section 1)
- 시험장에서 **"이게 {패턴} 문제인가?"** 판별 가능해야 한다.
- 문제 본문 키워드 카탈로그 + 제약조건(n, 시간제한) 매핑 표 박아라.
  - DP: "최대/최소 경우의 수", "방법의 수", "n번째", n ≤ 1000 + 부분문제 겹침
  - 그래프 BFS: "최단 거리", "최소 이동", 격자/노드 + 가중치 없음
  - 백트래킹: "모든 조합/순열", "가능한 모든 경우", n ≤ 15
  - 이분탐색: "최대값을 최소화", "k 이상 가능한 최소 X", 단조성
- 레퍼런스에서 패턴 정의 + 출제 키워드 전부 발췌해서 첫 섹션에 박는다.

### G4. 패턴 코어 메커니즘 1개 (진하게)
- DP = **"이전 상태로 현재 만들기"** (`dp[i] = f(dp[i-1], dp[i-2], ...)`)
- BFS = **"큐 + visited 체크 + 레벨 단위 확장"**
- DFS/백트래킹 = **"선택 → 재귀 → 되돌리기(undo)"**
- 투포인터 = **"두 포인터 조건에 따라 한쪽씩 이동"**
- 슬라이딩 윈도우 = **"윈도우 확장/축소로 조건 유지"**
- 이분탐색 = **"단조성 있는 답 공간을 절반씩 자르기"**
- 코어가 잡히면 **Section 3에 그 메커니즘만의 매트릭스 + 템플릿 코드**.

### G5. 분량 400~500줄
- 패턴 특성에 따라 ±20% 허용. **절대 600줄 초과 금지**.
- 한 섹션이 100줄 넘으면 멈추고 다른 섹션 압축 검토.
- 시험장에서 펴서 쓰는 자료 → Ctrl+F 한 번에 찾아야 한다.

### G6. 강사/레퍼런스 직접 인용 비율 ≥ 50%
- 코드 스니펫 옆 출처 표기 `*(LeetCode 70 공식 해설)*` / `*(백준 1260 신찬수 강의)*` 형식.
- 출처 없는 자작 코드는 카탈로그에 넣지 마.
- 레퍼런스 코드는 **변수명·구조 최대한 보존** (시험장에서 일관성 있게 외우려고).

## 3. 7섹션 골격 (이 구조 그대로)

### Section 1 — 패턴 식별 시그널 (이런 문제 나오면 발동)

- `> 패턴 정의` (블록 인용 한 문단, 레퍼런스에서 발췌)
- **1-1. 판별 키워드** (문제 본문에 나오면 의심할 단어 카탈로그)
- **1-2. 제약조건 시그널** (n ≤ ? / 시간제한 → 패턴 매칭 표)
- **1-3. 대표 출제 예시** (사용자 제공 문제 N개 한 줄 요약 + 링크)
- **1-4. 시험장 첫 5분 체크** (시그널 → 패턴 발동 매핑 표)

### Section 2 — 패턴 단계별 ★ 임무 (외울 핵심 5줄)

- 단계 표
  - DP: [상태 정의 → 점화식 → 초기값 → 순회 순서 → 답 위치]
  - BFS: [시작점 큐 삽입 → visited 체크 → 인접 노드 큐 → 거리 갱신 → 종료]
  - 백트래킹: [상태 정의 → 가지치기 조건 → 선택 → 재귀 → undo]
- **단계별 함정** (레퍼런스에서 X로 명시한 것 — 출처 표기 필수)
- 예: DP 초기값 누락, BFS visited 체크 위치(큐 push 시 vs pop 시), 백트래킹 undo 누락

### Section 3 — 패턴 코어 메커니즘 + 템플릿 코드

- **코어 메커니즘 한 문장** (G4 참조, 진하게 박아라)
- **템플릿 코드** (15~30줄, 변수만 바꾸면 80% 문제 풀리는 골격)
- **코어 메커니즘 매트릭스** (대표 문제 N개 × 코어 동작 발현 방식)

### Section 4 — 변형별 코드 카탈로그 (본체)

- 🟢 기본형 / 🟡 변형1 / 🟠 변형2 / 🔵 최적화 / 🟣 함정 케이스
- 각 박스 안: **코드 스니펫 → 출처 → 어디서 막히는지 메모**
- 한 변형 안에서 톤별 분류 (재귀/반복, 1D/2D, 메모이제이션/타뷸레이션)

### Section 5 — 보너스 규칙 (레퍼런스 직접 인용)

- 패턴 고유 규칙
  - DP: 점화식 먼저 종이에 → 코드는 마지막
  - BFS: 큐 자료구조 선택 (deque vs queue)
  - 백트래킹: 가지치기 우선순위
  - 이분탐색: lo/hi 경계 + 종료 조건 통일
- 시간·공간 복잡도 최적화 트릭
- **모든 규칙은 레퍼런스 인용 출처 표기 필수**

### 부록 A — 문제 × 패턴 요소 매트릭스

- 사용자 제공 문제 N개 × 패턴 요소(상태/전이/초기값/순회/답)
- 패턴 코어 요소가 문제마다 어떻게 변하는지 한눈에
- **검증 포인트** 3~5개 (자기 코드 작성 후 체크리스트)

### 부록 B — 기본형 vs 변형 차이 (실력 갈림길)

- 구조 차이 표
- 내용 차이 (레퍼런스 인용)
- 패턴 고유 함정 (DP 음수 인덱스, 그래프 사이클, 백트래킹 visited 처리)
- **실전 체크**: 자기 코드가 기본형인지 변형인지 신호

### + 메타 코멘트 (마지막 한 문단)

- "이번 결과는 {패턴} 카탈로그, 입력은 {문제 N개}"
- 패턴 코어 메커니즘 한 줄 요약

## 4. 작업 순서

사용자가 단계별 피드백 안 준다. 너 혼자 완성한다.

### 4-1. 정독 (10~15분)
1. 가장 기초 문제 + 레퍼런스 코드 정독
2. 빈출 변형 2~3개 + 레퍼런스 코드 정독
3. 레퍼런스에서 패턴 정의 + 핵심 동작 + 함정 명시한 부분 마크
4. `카탈로그/비교_A.md` 7섹션 골격 재확인

### 4-2. 패턴 코어 메커니즘 잡기
- "이 패턴이 통하는 핵심 동작 하나" 한 문장으로 정의
- 레퍼런스에서 그 동작 정의된 위치 출처 확보
- 대표 문제 N개에서 그 동작이 **코드로** 어떻게 발현됐는지 매트릭스 초안

→ **이게 안 잡히면 카탈로그 만들지 말고 사용자에게 보고**:
> "패턴 코어가 X로 잡히는데 레퍼런스 N과 문제 N개에서 일치 확인 필요"

### 4-3. 7섹션 골격 채우기
- Section 1~5 + 부록 A/B 순서대로
- 각 섹션 작성 후 G1~G6 자기 체크
- 한 섹션이 100줄 넘으면 → 멈추고 다른 섹션 압축 검토

### 4-4. 최종 자가 검증 (제출 전)
- 분량: 400~500줄 (±20%)
- 출처 표기 비율: 코드 블록의 **70% 이상**에 출처 박힘 (G6 인용 비율 ≥50% 보장)
- 추상 라벨: 새로 만든 분석가 라벨 **0개**
- 패턴 코어 메커니즘: Section 3에 템플릿 코드로 명확히 보임
- 레퍼런스 직접 함정 인용: Section 2 또는 5에 최소 5개
- **코드 컴파일/실행 가능 여부 자체 검토** (변수명 오타·들여쓰기·문법)

### 4-5. 산출물 저장
- 경로: `카탈로그/{패턴}_A.md`
- 예: `카탈로그/DP_A.md`, `카탈로그/그래프_A.md`, `카탈로그/백트래킹_A.md`

## 5. 메타 보고 (참조 비율 필수)

산출물 마지막에 다음 박스 박아라:

```markdown
## 📌 작업 메타 (참조 비율)

- 정독 문제: {문제 목록 N개 + 링크}
- 시드 카탈로그(비교_A.md) 참조 항목: 7섹션 골격, 출처 표기 형식, 이모지 마커
- 패턴 코어 메커니즘: {한 문장} (출처: {레퍼런스 위치})
- 신규 도입 코드 스니펫 수: {본문 코드 블록 개수}
- 레퍼런스 직접 인용 줄: {줄 수} / 자작 일반화 줄: {줄 수} → 인용 비율 {%}
- 가드레일 위반 자가 체크: G1~G6 통과 (또는 위반 항목 명시)
- 작업 시 발견한 패턴 고유 특이점: {1~2줄}
```

이 메타가 있어야 사용자가 **다른 패턴 카탈로그끼리 횡적 비교** 가능.

## 6. 사용자 톤

- 한국어
- 직설적, 군더더기 없음
- **시험장에서 꺼내 쓰는 자료**라는 의식 항상
- 코드는 복붙 가능한 형태, 변수명 일관, 들여쓰기 정확
- 분석 깊이는 사용자 본인 이해 가능한 선까지만

## 7. 시작 전 자가 체크리스트

작업 시작 직전 너 스스로 답해라:
1. 어느 패턴? 입력 문제 정확히 몇 개?
2. 패턴 코어 메커니즘 후보 가설은? (정독 전 임시 가설)
3. 결과물 저장 경로는? `카탈로그/{패턴}_A.md`
4. 7섹션 골격 그대로 가는가, 패턴 특성상 일부 압축할 항목 있는가?
   - 예: DP는 Section 5 보너스 규칙 비대해지기 쉬움 → 압축
   - 백트래킹은 Section 4 변형 비대해지기 쉬움 → 변형 수 제한
5. 사용 언어는? (Python / C++ / Java 중 하나로 통일, 섞지 마)

체크 끝나면 정독 시작.
