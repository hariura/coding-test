# 🎯 코딩테스트 약점 체크리스트

> 오픽 IH 합격(2026-05-31)에서 추출한 [학습_메타_노트](../학습_메타_노트.md)의
> **반복 실수 패턴 + 약점 속도 3분류 법칙**을 코딩테스트로 일반화한 운영 매뉴얼.
> 시험장(코딩테스트) 들어가기 전·푸는 중·제출 전에 펴서 본다.

---

## 0. 핵심 한 줄

> **약점은 3종류뿐이다 — ① 알면 끝나는 것 / ② 트리거 박아야 하는 것 / ③ 자발 기다리는 것.**
> 종류 잘못 분류하면 평생 못 고친다. "조심하자"로는 ②번을 못 잡는다.

---

## 1. 인지 ≠ 실행 약점 (트리거로 박기)

> **오픽 ER 시제 일관성과 등가 구조**:
> 머리로는 알지만 실행 중(코딩 중)엔 자동으로 빠지는 약점.
> 매번 들어가는 진입 지점에 **자동 스위치(트리거)**를 박아야 잡힌다.
> "조심하자"는 안 통한다 — 시제 #11·#12·#13 3회 연속 미해결로 검증됨.

| 약점 | 진입 트리거 (워크플로우에 박기) |
|---|---|
| **엣지케이스 빠뜨림** | 코딩 전 손으로 5개 적기: `빈 입력 / 1개 / 최대값 / 음수 / 중복` |
| **시간복잡도 안 따짐** | 코딩 전 **N 범위 확인** → O(?) 가능 계산 (N=10^5면 O(N log N)까지) |
| **변수명 일관성** | `i/j/k` 통일 / `nums/arr` 통일 — 중간 바꾸지 X |
| **off-by-one** | for 루프 끝마다 `idx +1/-1` 검토 / `<` vs `<=` 검토 |
| **입출력 형식 오타** | 제출 전 마지막 1줄: "출력 형식 다시 봐라" |

### 트리거 박는 메커니즘 (오픽 시제 깃발과 동일)
- ❌ "엣지케이스 조심하자" — **안 통함**. 급하면 빼먹음.
- ✅ "문제 읽자마자 → **엣지케이스 5개 손으로 종이에 적기**" — **자동 스위치**.
- = 시제를 "단원 진입 깃발"로 잡은 것과 동일. **자동 스위치를 워크플로우에 박아넣기.**

### 트리거 설계 원칙 3가지
1. **언제** 발동되는가가 명확해야 한다 ("문제 받자마자" / "제출 누르기 전" 같은 물리적 지점)
2. **무엇**을 하는지 손에 박혀야 한다 ("5개 적기" 같은 정량 액션 — 추상 X)
3. **빠뜨리면 안 넘어간다**는 강제 규칙 (오픽: 단원 깃발 안 박으면 답변 시작 X)

## 2. 자기 함정 (학습_메타_노트의 강점/함정 그대로 이전)

### ✅ 강점 (코딩테스트에서도 보존)

| 강점 | 코딩 적용 |
|---|---|
| **변형 능력** | 낯선 문제 → "이거 결국 ~문제구나" 아는 유형으로 환원 |
| **골격 차용** | 검증된 템플릿(BFS/DFS/투포인터)에 이 문제 조건만 끼워넣기. **백지 X** |
| **메타인지** | 자기 시제 본인이 알아챈 경향 → 코딩에서 **자기 버그 본인이 잡는 능력** |
| **검증된 것만 신뢰** | 정답 코드 + 명시적 패턴(에디토리얼) + 내 오답 분석만. 감으로 만든 규칙 X |

### ⚠️ 함정 (반복 회피)

| 함정 | 코딩에서 어떻게 나타나는가 |
|---|---|
| **갈래로 빠지는 경향** | 재귀 깊이 무한히 들어감 / 최적화 너무 일찍 / 한 접근법 끝까지 안 가고 다른 방법 기웃 |
| **추상 라벨 만들기** | "내가 만든 패턴" 이름 금지. 출처 없는 분류 만들다 시간 낭비 |
| **한 번에 너무 많이** | 한 번에 약점 1~2개만. 한 번에 최적화 X — 일단 돌아가는 코드부터 |
| **강요 거부** | 어려운 패턴(DP/그리디 증명) 강요 거부 OK = "아직 준비 안 됨"이지 "영원히 못 함"이 아님. 자기 수준 인내 |

> **핵심**: 함정은 강점의 그림자다. 변형 능력의 그림자가 "갈래로 빠짐", 메타인지의 그림자가 "추상 라벨 만들기". 강점을 살리되 그림자는 트리거로 막는다.

### 강점/함정 페어 매핑

- **변형 능력 ↔ 갈래로 빠짐**: 환원할 후보가 너무 많이 떠오를 때 한 개만 고르고 끝까지.
- **메타인지 ↔ 추상 라벨**: 자기 분석이 깊어지면 자꾸 새 분류를 만든다. 기존 유형명만 사용.
- **검증된 것만 신뢰 ↔ 강요 거부**: 신뢰하는 소스만 받으니 새 패러다임 진입이 느림. 노출 반복으로 우회.

## 3. 약점 속도 3분류 법칙 ★ (학습_메타_노트 5번)

> **이 분류가 약점 체크리스트의 엔진이다.**
> 약점을 만나면 먼저 **이게 어느 종류인지** 판단부터. 분류 잘못하면 처방도 틀린다.

| 약점 종류 | 극복 방식 | 코딩 예시 | 오픽 등가 |
|---|---|---|---|
| **① 명확한 규칙** (인지에 들어옴) | **즉시** 다음 시도에 적용. 1회만 알면 됨 | "엣지케이스 손으로 5개" / 특정 API 실수 / 템플릿 누락 | #15→#16 부정 받아치기 (1회 극복) |
| **② 자동화 필요** (트리거 박기) | 매번 들어가는 지점에 **트리거** 박기 | "코딩 전 N 범위 보기" / 제출 전 반례 1개 / off-by-one 검토 | #11~22 시제 일관성 (트리거 만들 때까지 중간 속도) |
| **③ 정체성 거부** (자기 수준) | **인내**. 자발 올 때까지 기다림. 강요 X, 노출 O | "DP 사고법 거부" / "그리디 증명 거부" — 양치기 누적 | #7→#12 깨달음 단계 (5회 노출 후 자발) |

### 분류 판별법

```
약점 만남
  ↓
"한 번 알면 다음에 안 틀릴 것 같은가?" → YES → ① 명확한 규칙 → 즉시 적용
  ↓ NO
"알지만 실행 중 자동으로 빠지는가?" → YES → ② 자동화 → 트리거 박기
  ↓ NO
"내 수준/사고방식 자체를 바꿔야 하는가?" → YES → ③ 정체성 → 인내, 노출 반복
```

### 분류별 처방 차이 (잘못 분류하면 평생 못 고침)

- **①을 ②로 처방**: 트리거 만드느라 시간 낭비. 그냥 알면 끝남.
- **②를 ①로 처방**: "조심하자" — 시제 #11·#12·#13처럼 3회 연속 미해결.
- **③을 ①·②로 처방**: 강요됨 → 거부 → 학습 자체 차단. 노출만 계속.

### 분류 예시 모음 (실제 약점을 어디로 분류할지)

| 약점 | 분류 | 근거 |
|---|---|---|
| `input()` 대신 `sys.stdin.readline()` 안 쓰면 TLE | ① | 한 번 알면 다음엔 자동으로 씀 |
| 재귀 한도 `sys.setrecursionlimit` 누락 | ① | 한 줄 박으면 끝 |
| `dict.get(key, 0)` 같은 디폴트값 누락 | ② | 매번 실수 — 진입 트리거 필요 |
| 인덱스 범위 `n-1` vs `n` | ② | 매번 헷갈림. 제출 전 검토 트리거 |
| DP 점화식 자력 도출 | ③ | 사고법 자체가 안 박힘. 노출 누적 필요 |
| 그리디 증명 능력 | ③ | 정체성 — 직관으로 안 풀리면 거부 본능 |

## 4. 제출 전 체크리스트 5단계 ★

> **오픽 T 짝짓기(마무리)와 등가**. 내 고질 약점 = "마무리 흐지부지". 매번 빼먹음.
> **트리거로 강제**해야 잡힌다. 제출 버튼 누르기 전 무조건 5개 실행.

```
┌─────────────────────────────────────────┐
│  제출 전 5단계 (트리거: 제출 버튼)        │
├─────────────────────────────────────────┤
│  1. 입출력 형식 다시 확인 (오타?)         │
│  2. 엣지케이스 1개 손으로                │
│     (빈 입력 or 최대값 직접 추적)         │
│  3. 시간복잡도 계산 (TLE 위험?)           │
│  4. 변수명 일관성 확인                   │
│  5. off-by-one 인덱스 검토               │
│     (`<` vs `<=`, +1/-1)                │
└─────────────────────────────────────────┘
```

### 각 단계 디테일

1. **입출력 형식** — 공백/줄바꿈/대소문자/`endl` vs `\n`. 가장 멍청하게 0점 받는 지점.
2. **엣지케이스 1개 손으로** — 머릿속 X. **종이에 입력→출력 한 줄씩** 추적. 빈 입력 또는 N=최대값.
3. **시간복잡도** — N 다시 보고 O 계산. N=10^5에 O(N²)이면 TLE 확정.
4. **변수명 일관성** — 중간에 `i`를 `idx`로 바꿨거나, `nums`를 `arr`로 섞었으면 위험 신호.
5. **off-by-one** — for 루프 끝 인덱스, 배열 길이 ±1, 슬라이싱 끝점. 가장 자주 빠짐.

### 왜 이 5개인가
- 1·5 = 멍청한 실수 (③ 정체성 거부 약점은 여기 없음)
- 2·3 = 자동화 필요 (②번. 시제 일관성 = 엣지케이스와 등가)
- 4 = 자기 함정 (변수명 갈래로 빠짐)

### 발동 강제 룰

- 제출 버튼 누르기 전 **5개를 종이에 ✓ 표시**하기 전엔 클릭 금지.
- 시간 부족하면 **2번(엣지 손추적)·3번(복잡도)·5번(off-by-one)** 최소 3개는 무조건.
- 빠뜨린 단계가 매번 같으면 → 그 단계는 ② 약점 → 트리거를 더 물리적으로 (포스트잇·알람).

## 5. 양치기 누적 후 변화 추적 (코테_기록.md 갱신용)

> 오픽 시험_기록.md의 **약점 추적 매트릭스**와 동일 구조.
> "다음 향상 포인트"로 박은 약점이 시간이 지나면서 어떻게 움직이는지 추적.

### 5-1. 추적 원칙

| 패턴 | 판단 | 처방 |
|---|---|---|
| 한 번에 극복된 약점 | **① 명확한 규칙**이었음 | 다음 약점으로 진입. 더 신경 X |
| N회 후에도 미해결 | **② 자동화 필요인데 ①로 처방 중** | 트리거 다시 디자인. "조심"에서 "워크플로우 단계"로 |
| 강요할수록 더 안 됨 | **③ 정체성** | 강요 중단. 노출만 유지. 자발 기다림 |

### 5-2. 매트릭스 양식 (코테_기록.md에 박을 것)

```
| 유형  | 약점         | #1 | #2 | #3 | #4 | #5 | 분류 | 처방            |
|------|-------------|----|----|----|----|----|------|----------------|
| BFS  | 방문체크 누락 | X  | X  | O  | O  | O  | ①    | 1회로 끝       |
| DP   | 점화식 잘못  | X  | X  | X  | X  | X  | ③    | 노출만 누적     |
| 공통 | off-by-one  | X  | X  | X  | O  | X  | ②    | 트리거 재설계   |
```
- **X = 그 시도에 그 약점 발생 / O = 극복**
- **분류**: ①명확 / ②자동화 / ③정체성
- **처방**: 분류에 맞춰 다르게

### 5-3. 분류 재진단 시그널

- **3회 이상 미해결** → "①인 줄 알았는데 사실 ②다." 트리거 박아야 함.
- **5회 이상 미해결 + 강요됐을 때 거부감** → "②인 줄 알았는데 사실 ③이다." 강요 중단.
- **1회 만에 해결 + 다음 회차도 유지** → ①. 다음 약점으로.

### 5-4. 양치기 3요소 적용 (#15→#16에서 통한 것)

1. **즉각성** — 틀린 문제 → **바로** 유사 문제 재시도. 시간 끌면 효과 ↓
2. **같은 골격 / 다른 표면** — 투포인터 5문제 / DP 5문제 연속. 유형은 동일, 표면만 바꿈
3. **집중 (1~2개만)** — 재시도 시 약점 1개만 의식. "이번엔 엣지케이스만" / "이번엔 시간복잡도만"

### 5-5. 변화 추적 캘린더 (월 단위)

- **월말 점검**: 매트릭스의 ② 약점들이 X→O로 움직였는가?
  - 움직였다 → 트리거 작동 중. 유지.
  - 안 움직였다 → 트리거 재설계 또는 ③으로 재분류.
- **다음 향상 포인트 회전 룰**: 한 약점이 3회 연속 O면 매트릭스에서 빼고, 다음 ② 후보를 올린다.
- **③ 약점은 매트릭스 하단 별도 영역에** "노출 누적 카운터"로만 관리. X/O 점수 X.

## 📌 부록 A — 한 장 요약 (시험장 직전용)

### 문제 받자마자 (코딩 전)
1. 🔒 **앵커 4개**: 자료구조 / 알고리즘 유형 / 시간복잡도 목표 / **엣지케이스 5개 손으로**
2. "이거 아는 유형으로 환원하면 ~문제" (변형)
3. 검증된 템플릿 골격 떠올리기 — **백지 X**

### 푸는 중
4. 막히면 **brute force라도 일단 돌아가게** (완벽 추구로 멈추지 마)
5. **한 접근법 정하면 끝까지** (갈래로 빠지지 마)
6. **추상 라벨 만들지 마** (내가 만든 패턴 이름 X)

### 제출 전 (★ 트리거)
7. 입출력 형식 / 엣지케이스 1개 손으로 / 시간복잡도 / 변수명 / off-by-one — **5개 다**

### 복습
8. 틀린 문제 → **즉시 유사 문제 재시도** (양치기 즉각성)
9. 약점 매트릭스에 기록 — **분류 (①/②/③)** 박기
10. 3회 미해결 → 분류 재진단

## 📌 부록 B — 자주 헷갈리는 분류 (FAQ)

**Q. "엣지케이스 빠뜨림"은 ①인가 ②인가?**
A. ②. 한 번 알아도 다음에 또 빠뜨림 — 시제 일관성과 동일 구조. 진입 트리거 필수.

**Q. "DP를 못 푼다"는 ②인가 ③인가?**
A. 두 층이 섞여있다. **DP 템플릿 외우기 = ②** (자동화), **DP 사고법(점화식 자력 도출) = ③** (정체성). 분리해서 처방.

**Q. 새 패턴을 만나면 항상 ③인가?**
A. 아니다. 보통 ① + ② 조합. 패턴 정의(①) + 적용 트리거(②). ③은 사고방식 자체를 바꿔야 할 때만.

**Q. 트리거를 박았는데도 안 통하면?**
A. 트리거 설계 원칙 3가지 점검 — ① 언제 발동? ② 무엇을 하는지 정량적? ③ 안 하면 못 넘어가는 강제력? 셋 다 충족 안 됐을 가능성.

**Q. ③ 약점은 언제 ②로 내려오나?**
A. 노출이 누적되어 "이 패턴 보면 어디서 시작할지 감이 온다"는 순간. #7→#12처럼 5회 정도 노출 후 자발이 일반적. 그때 비로소 트리거 박을 만한 ②가 됨.

**Q. 양치기 5문제는 같은 사이트에서? 다른 사이트에서?**
A. **같은 골격 / 다른 표면** 원칙. 같은 유형이면 사이트 무관. 다만 입출력 형식이 달라지면 ② 약점(입출력 오타)도 같이 양치기됨 — 보너스.
