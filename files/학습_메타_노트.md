# 🧠 내 학습 메타 노트 (도메인 무관 — 코딩테스트·시험 이전용)

> 오픽 IH 합격(2026-05-31)까지의 "양치기 학습"에서 추출한 **나만의 학습 방법론**.
> 일반 학습법이 아니라 **내 성향에 맞춰 검증된 방식**. 코딩테스트 풀 때 펴서 본다.
> 근거: 오픽 모의시험 #1~#43 누적 데이터 (사례 번호로 출처 표기).

## 0. 핵심 한 줄

> **검증된 골격에 내 것을 끼워넣고 → 약점 1~2개만 집어서 → 즉시 재시도.**
> 이게 내 학습 엔진. 새 걸 통째로 만들지 않고, 있는 걸 변형·재사용한다.

## 1. 내 학습 성향 (이게 나다)

### 1-1. 시작 전 접근법 — "앵커부터 정한다"
- 문제 받으면 **답을 바로 시작하지 않고, 핵심 단어 N개부터 고정**한다.
  - (오픽) 답변 전 "4단어"(토픽/부속/시동/평결) 또는 "부속 2단어"를 먼저 못박음
  - **→ 코딩 이전**: 문제 읽고 **바로 코딩 X**. 먼저 정할 것 = ① 자료구조 ② 알고리즘 유형 ③ 시간복잡도 목표 ④ 엣지케이스. **이 4개 앵커가 정해지면 코드가 자동으로 굴러간다.**
- **골격 차용 + 표면 변형**: 검증된 구조(강의 답안)를 가져와 내 토픽만 갈아끼움.
  - **→ 코딩**: 검증된 템플릿(BFS/DFS/투포인터 골격)에 이 문제의 조건만 끼워넣기. 백지에서 짜지 않는다.

### 1-2. 어디서 막히는가 (막힘 지점 지도)
| 단계 | 나의 상태 |
|---|---|
| **구조/골격** | ✅ 빨리 잡음 (제일 강함) |
| **세부 실행(표현/문법)** | ⚠️ 막힘 — 정확한 단어/문법 인출에서 멈춤 |
| **마무리(닫기)** | 🔴 자주 흐지부지 (T 짝짓기 = 고질) |
| **자신감/컨디션** | 🔴 영향 큼 — 워밍업 안 되면 쉬운 것도 막힘 (아침 입 안 풀림) |

- **→ 코딩 이전**:
  - 구조(접근법)는 빨리 떠올림 = 강점 유지
  - 막힘 = **세부 구현**(문법/API/인덱스 실수) + **마무리**(제출 전 검증 빼먹음)
  - **워밍업 필수** — 시험 전 쉬운 문제 1~2개로 손 풀기 (오픽에서 입 풀듯)

### 1-3. 피드백을 수용하는 두 가지 모드
- **(A) 즉시 적용** — 피드백 직후 바로 다음 시도에 반영 (양치기 효과). 명확한 골격이면 1회 만에 적용.
- **(B) 거부 후 자발** — 내 수준 밖이라 느끼면 일단 거부 → 노출 반복되면 나중에 스스로 시도 (#7 거부 → #12 자발, 5회 뒤).
- **→ 핵심**: 나는 **강요받으면 거부**한다. 준비되면 스스로 한다. (코칭/스스로에게: 강요 X, 노출 반복 O)

### 1-4. 무엇을 보고 인사이트를 얻는가 (신뢰 소스)
- ✅ **검증된 모범답안** (내 답 기반으로 최소 수정한 것) — 가장 신뢰
- ✅ **명시적 규칙/출처** ("강사가 직접 박은 것", 출처 있는 것) — 신뢰
- ✅ **자기 분석/메타 인식** (#12에서 시제 약점 본인이 알아챔)
- ❌ **출처 불명확한 추상 라벨** — 거부 (분석가가 만든 "관찰형/REASON형" 같은 거)
- **→ 코딩**: 신뢰할 소스 = 정답 코드(검증됨) + 명시적 패턴(에디토리얼) + 내 오답 분석. **불명확한 "감"으로 만든 규칙은 안 믿음.**

## 2. 반복 실수 패턴 (가장 단단한 약점)

### 2-1. "박혔는데 매번 빼먹는" 패턴
- **사례**: 시제 일관성 — #11·#12·#13 **3회 연속** 미해결. "다음 향상 포인트"로 매번 기록했는데도 안 박힘.
- **왜 안 박혔나** 🔑: **인지(머리로 앎) ≠ 실행(실시간 자동)**. 의식하면 되지만, **실행 중(말하는 중)엔 자동으로 빠짐.** 알아도 급하면 빠지는 것.
- **무엇이 결국 통했나**: 콤보셋 5에서 **"단원 진입 시 시제 모드 깃발"**을 만들고 나서야 극복. = **의식 트리거를 골격에 박아넣음** (그냥 "조심하자"가 아니라 "이 유형 = 이 모드"라는 자동 스위치).

### 2-2. 코딩테스트로 일반화
"알지만 급하면 빼먹는" 것들 = 내 시제 약점과 같은 구조:
| 오픽 | 코딩테스트 등가물 |
|---|---|
| 시제 일관성 | **엣지 케이스** (빈 입력 / null / 단일 원소 / 오버플로우) |
| 마무리(T 짝짓기) | **제출 전 테스트** / 반례 확인 |
| be동사 누락 | **off-by-one** / 인덱스 경계 |
| because of | **시간복잡도 확인** 빼먹기 |

- **처방 (시제에서 통한 방법 그대로)**: "조심하자"는 안 통함. **진입 트리거**를 만들어라:
  > "문제 읽자마자 → **엣지케이스 3개 먼저 적기**(빈 입력/최대값/단일)"
  > "제출 누르기 전 → **반례 1개 손으로 돌리기**"
  - = 시제를 "단원 진입 깃발"로 잡은 것과 동일 메커니즘. **자동 스위치를 워크플로우에 박아넣기.**

## 3. 양치기 효과 (역대 최대 #15 → #16, +1.25점)

### 3-1. 왜 통했나
- 같은 유형(문제해결 롤플레이) **다른 토픽**(새 식당 → 엄마 아픔)으로 **피드백 직후 즉시 재시도**.
- 약점 2개(부정 받아치기 + 마무리)를 명확히 집어준 직후 → **1회 만에 둘 다 극복.**

### 3-2. 양치기 핵심 3요소 + 2 보조 메커니즘 (단일 박스)

| 구분 | 요소 | 역할 |
|---|---|---|
| **3요소** (발동 시 즉시 충족) | ① **즉각성** | 피드백 직후 재시도 (시간 끌면 효과 ↓) |
| | ② **같은 골격 / 다른 표면** | 유형 동일, 토픽만 바꿈 (구조 반복 + 적용 다양화) |
| | ③ **집중 (1~2개만)** | 한 번에 약점 1~2개. 다 고치려 하면 과부하 |
| **2 보조** (장기 작동) | ④ **누적** (매트릭스 추적) | 시도·결과·약점을 기록에 쌓아 패턴 드러내기 → `시험_기록.md` / `코테_기록.md` |
| | ⑤ **트리거** (인지≠실행 약점 박기) | 매번 빼먹는 약점에 진입 지점 알람 → `약점_체크리스트.md` |

> **3요소 = 한 번의 양치기 사이클에 필요한 조건** / **2 보조 = 양치기를 시스템으로 굴리는 인프라**.
> #15 → #16 +1.25점 폭발은 3요소만으로도 가능했고, 누적·트리거는 그 폭발이 일회성이 아니라 시스템이 되게 함.

### 3-3. 코딩테스트 양치기 설계
- **같은 알고리즘 유형 연속 풀기** — 투포인터 5문제 / DP 5문제 (오픽 "같은 유형 다른 토픽"과 동일)
- **틀린 문제 → 즉시 유사 문제 재시도** (#15→#16처럼 즉각성)
- **패턴별로 묶어서** — 흩어 풀지 말고 유형 클러스터로 (골격 반복이 핵심)
- **재시도 시 약점 1개만 의식** — "이번엔 엣지케이스만" / "이번엔 시간복잡도만"

## 4. 즉각 대응 메커니즘 (모르는 것 만났을 때)

### 4-1. 오픽에서 통한 것
- **토픽 변형**: 모르는/낯선 토픽 → **아는 토픽으로 치환** (Taiwan → Japan, 모르는 공원 → 아는 공원)
- **골격 차용**: 검증된 구조에 끼워넣기 (내용 몰라도 틀은 굴러감)
- **막히면 우회**: 완벽한 단어 포기, **쉬운 말로 직진** (`harmonic` 안 떠오르면 "the lights matched the music")

### 4-2. 코딩테스트 일반화
| 오픽 | 코딩 |
|---|---|
| 낯선 토픽 → 아는 토픽 치환 | **모르는 문제 → 아는 유형으로 환원** ("이거 결국 ~문제구나") |
| 골격 차용 | **검증된 템플릿 적용** (BFS/DFS/이분탐색 골격) |
| 막히면 쉬운 말 직진 | **막히면 brute force라도 일단 제출** (0점보단 부분점수) |
| 어려운 단어 우회 | **어려운 자료구조 안 떠오르면 단순한 걸로** (set/dict로 일단) |
- **핵심 원칙**: 완벽 추구하다 멈추는 게 최악. **불완전해도 끝까지 굴러가는 것**이 점수다. (오픽 "막혀도 직진" = 코딩 "일단 돌아가는 코드부터")

## 5. 약점 극복 사례 분석 (각각 무엇이 작동했나)

| 사례 | 약점 | 극복 속도 | 무엇이 통했나 |
|---|---|---|---|
| #7→#12 | 고차원 시도(깨달음 단계) 거부 | **느림 (5회)** | 강요 X + 노출 반복 → 자발 |
| #15→#16 | 명확한 메커니즘 2개 | **즉시 (1회)** | 골격이 명확 → 바로 적용 |
| #4→#11 | 특정 시그널 실패 | **중간 (누적)** | 같은 유형 여러 번 반복 누적 |
| 시제 #11~22 | 실행 자동화 | **중간 (트리거 만들 때까지)** | "진입 깃발" 트리거 추가 |

### 5-1. 극복 속도를 가르는 법칙 🔑
- **명확한 골격/규칙이 있는 약점** → **빠름** (즉시~1회). 집어주면 바로 됨.
- **실행 자동화가 필요한 약점** → **중간**. 트리거(자동 스위치)를 만들어야 됨.
- **내 정체성/수준을 바꿔야 하는 약점** → **느림**. 강요하면 거부, 노출 반복으로 자발 기다림.

### 5-2. 코딩테스트 적용
- **빠른 것** (집어주면 즉시): 특정 API/문법 실수, 템플릿 누락 → 바로 고침
- **중간** (트리거 필요): 엣지케이스, 시간복잡도, 제출 전 검증 → 워크플로우에 단계 박기
- **느린 것** (자발 기다림): 새 패러다임(DP 사고법, 그리디 증명) → 강요 말고 노출·반복으로 체화
- **→ 내 약점을 이 3분류로 먼저 나눠라.** 빠른 건 바로, 중간은 트리거, 느린 건 인내.

```
│
├── 패턴 카탈로그 (유형별 템플릿 — BFS/DP/투포인터 골격 + 코어 한 줄)

```

- **개별 기록 양식**: 답안(코드)을 **내 풀이 기반 + 정답 골격 최소 차용**으로 (통째 베끼기 X — 오픽 모범답안 fidelity 원칙 그대로).

## 7. 내 강점 / 함정 (반드시 보존 / 반드시 회피)

### ✅ 강점 (코딩테스트에서도 살릴 것)
1. **변형 능력** — 검증된 것에 내 케이스 끼워넣기 (낯선 것을 아는 것으로 환원)
2. **자기 것 유지 + 골격만 차용** — 통째로 베끼지 않음. 내 풀이 살리고 구조만 빌림 → 진짜 내 실력 됨
3. **약점 자기 인식** — 스스로 "여기서 막혔다" 알아챔 (#12 시제 자가 진단). 메타인지 강함
4. **검증된 것만 신뢰** — 출처 불명확한 "감"에 안 휘둘림

### ⚠️ 함정 (반복 회피)
1. **갈래로 빠짐 (분석 트리 증식)** — 한 점에 집중 못 하고 곁가지로 샘.
   - **→ 코딩**: 한 접근법 끝까지 안 가고 자꾸 다른 방법 기웃 → **하나 정하면 끝까지** (오픽 "한 점 못박기")
2. **추상 라벨 만들기** — 출처 없는 분류 만들다 시간 낭비.
   - **→ 코딩**: 과도한 추상화/설계 X. **돌아가는 단순한 것부터.**
3. **한 번에 너무 많이 고치기** — 과부하.
   - **→ 코딩**: 한 번에 약점 1~2개만. 다 잡으려다 다 놓침.
4. **자기 수준 밖 강요 거부** (양날의 검) — 보호막이자 한계.
   - **→ 코딩**: 새 패러다임(DP 등) 거부 본능 → **강요 말되, 노출은 계속** (#7→#12처럼 결국 자발 온다). 거부 = "아직 준비 안 됨"이지 "영원히 못 함"이 아님.
