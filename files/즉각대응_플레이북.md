# 코딩테스트 즉각 대응 플레이북

> 오픽의 "모르는 토픽 즉각 대응 + 변형 + 골격 차용" 전략을 코딩테스트로 일반화한 문서.
> 시험장에서 처음 보는 문제를 만났을 때 패닉 없이 점수 확보하는 절차.

---

## 0. 이 문서가 해결하려는 것

오픽에서 모르는 토픽 나와도 "기존 카탈로그 변형 + 골격 차용"으로 IH/AL 답안 뽑아냈듯,
코테에서도 모르는 문제 나와도 **30초 패턴 식별 → 변형 → 골격 차용**으로 부분 점수 이상 확보.

핵심 등가:
- 오픽 카탈로그 = 코테 알고리즘 패턴 매트릭스 (DP / 그래프 / 투포인터 / 해시 등)
- 오픽 모범답안 골격 = 코테 알고리즘 템플릿 코드 (다익스트라 / BFS / 슬라이딩 윈도우 등)
- 오픽 양치기 = 코테 유형별 반복 풀이
- 오픽 4층 채점 (카탈로그/콤보/감정/Transition) = 코테 4층 점검 (패턴/자료구조/복잡도/엣지)

---

## 1. 모르는 문제 만났을 때 30초 안에 (5단계)

문제 읽자마자 머리 비우고 이 순서 그대로. 절대 순서 바꾸지 말 것.

### 1단계. 입출력 예제 → 작은 예제 손풀이 (n=2, n=3)
- 문제 설명 길어도 일단 입출력 예제부터 봄.
- N=2, N=3 같은 가장 작은 경우 손으로 종이에 돌려봄.
- 이걸 안 하고 코딩 시작하면 99% 헛코딩.
- 손풀이 안 되는 문제는 코드로도 못 풂. 손풀이 = 알고리즘 발견 도구.

### 2단계. 비슷한 패턴 회상 (카탈로그 부록 A 매트릭스)
- "이거 본 적 있다" 감각 → 어느 카탈로그?
  - 배열 + 연속 구간 합 → 누적합 / 슬라이딩 윈도우
  - 그래프 + 최단 거리 → BFS (가중치 X) / 다익스트라 (가중치 O)
  - 선택/포함 여부 → DP / 백트래킹
  - 정렬해놓고 두 끝 → 투포인터
  - 빈도 / 존재 여부 → 해시 (dict/set)
  - 범위에서 답 찾기 → 이진탐색 / 파라메트릭 서치
  - 우선순위 처리 → 힙 (heapq)
  - 구간 갱신/조회 → 세그먼트 트리 / Fenwick
- 30초 안에 패턴 안 잡히면 → 일단 3단계 (brute force)로 넘어감.

### 3단계. Brute force 먼저 코딩 (TLE라도 부분 점수)
- 최적해 욕심 버림. 무식한 거 먼저.
- 2중/3중 for문이라도 됨. 일단 정답이 나오는 코드.
- TLE 나도 부분 점수 / 또는 패턴 발견 단서.
- Brute force가 통과되면 그게 정답. 욕심내지 말 것.

### 4단계. 시간복잡도 계산 (N 범위 보고 TLE 위험 측정)
- N 범위 보고 허용 복잡도 판단:
  - N ≤ 10 → O(N!) OK (순열 brute force)
  - N ≤ 20 → O(2^N) OK (비트마스크 / 부분집합)
  - N ≤ 100 → O(N^3) OK (플로이드)
  - N ≤ 1,000 → O(N^2) OK (DP 2차원)
  - N ≤ 100,000 → O(N log N) (정렬 / 이진탐색)
  - N ≤ 1,000,000 → O(N) 또는 O(N log N)
  - N ≤ 10^9 → O(log N) (이진탐색 / 수학)
- Brute force가 위 한계 초과면 → 5단계 최적화.

### 5단계. 최적화 패턴 적용 (DP / 투포인터 / 해시 / 이진탐색 등)
- 중복 계산 → 메모이제이션 (DP)
- 2중 for문 → 투포인터 / 슬라이딩 윈도우
- 매번 탐색 → 해시 / 정렬 후 이진탐색
- 매번 재계산 → 누적합 / 세그먼트 트리
- 같은 그래프 반복 BFS → 다익스트라 / 플로이드

## 2. 변형 / 골격 차용 (오픽 양치기 등가)

### 토픽 변형 = 입력 변형
오픽: Taiwan 여행 → Japan 여행으로 통째 갈아끼움.
코테:
- 배열 문제 → 문자열 문제로 동일 골격 (배열 = char 배열)
- N=10 그리디 → N=10^5 그리디 (자료구조만 dict/heap으로 바꿈)
- 1차원 DP → 2차원 DP (상태 하나 추가)
- 트리 DFS → 그래프 DFS (visited 배열 추가)
- 정수 이진탐색 → 실수 이진탐색 (종료 조건만 epsilon으로)

### 골격 차용 = 알고리즘 템플릿 그대로
오픽: A20 답안 골격 (감정→이유→예시→결론) 그대로 다른 토픽에.
코테:
- 다익스트라 코드 → 비슷한 가중치 그래프 문제에 그대로 (입력 파싱만 바꿈)
- BFS 코드 → 미로/최단경로/네트워크 전부 동일 골격
- 슬라이딩 윈도우 → 연속 부분 배열 문제 전부
- 이분탐색 파라메트릭 → "최소/최대값 구하기" 패턴 전부

**준비물**: 자주 쓰는 알고리즘 템플릿 5~10개를 외워서 시험장에서 30초 안에 타이핑 가능해야 함.
- BFS / DFS
- 다익스트라
- 이진탐색 (lower_bound / 파라메트릭)
- 슬라이딩 윈도우
- 누적합
- Union-Find
- 위상정렬
- LIS (O(N log N) 버전)

골격은 "본인 손으로 30초 안에 빈 종이에 재현 가능"해야 진짜 외운 것.

## 3. 우회 패턴 (어려운 거 → 만만한 거로)

오픽에서 어려운 표현 안 떠오르면 쉬운 표현으로 우회했던 것처럼.

| 어려운 거 | 만만한 우회 |
|---|---|
| DP 점화식 | 메모이제이션 재귀로 시작 (top-down) |
| 다익스트라 | BFS로 시작 (가중치 같으면 정답, 아니면 단서) |
| 세그먼트 트리 | 일단 brute force (N 작으면 통과) |
| 시간 모자람 | brute force 제출 (부분 점수 확보) |
| 자료구조 결정 못함 | dict / set / list 셋 다 시도 |
| 그리디 증명 못함 | 그냥 제출 (반례 안 떠오르면 맞을 확률 높음) |
| 비트마스크 헷갈림 | 일반 set / dict로 상태 표현 |
| 위상정렬 헷갈림 | DFS 후위순회로 대체 |

핵심: **시험장에서는 최적해보다 일단 통과되는 해가 우선**.
멋있는 코드 > 통과되는 코드 = 절대 X. 통과 > 멋. 무조건.

## 4. 막혔을 때 체크리스트

10분 이상 안 풀리면 무조건 이 순서.

1. **입출력 형식 다시 읽기** (오타? 인덱스 0/1 헷갈림? 출력 줄바꿈?)
2. **예제 손으로 풀어보기** (가장 작은 케이스 N=1, N=2)
3. **비슷한 문제 회상** (전에 풀었던 문제 중 골격 비슷한 거?)
4. **자료구조 바꿔보기** (list → dict, dict → heap, set → list)
5. **재귀 → 반복 또는 반대로** (재귀가 안 풀리면 반복문 DP로, 반대도)

위 5개 다 해도 안 되면 → 다음 문제로 넘어가고 나중에 돌아옴.

같은 문제 30분 박혀 있는 게 가장 큰 점수 손실. 다른 문제 1개 통과시키는 게 훨씬 이득.

## 5. 시간 분배 (1시간 1문제 기준)

| 시간대 | 할 일 | 멈춤 신호 |
|---|---|---|
| 0~5분 | 문제 정독 + 패턴 식별 (Section 1의 1~2단계) | 5분 넘게 패턴 안 잡히면 brute force로 직행 |
| 5~15분 | 작은 예제 손풀이 + 알고리즘 설계 | 15분 넘게 설계 못하면 brute force 코딩 시작 |
| 15~45분 | 코딩 (brute force → 최적화) | 45분에 답 안 나오면 부분 점수 모드 |
| 45~55분 | 디버깅 + 엣지케이스 (N=1, 빈 입력, 최대값) | 55분에 못 잡으면 그대로 제출 |
| 55~60분 | 제출 전 검증 (체크리스트 5단계) | — |

### 여러 문제 동시 풀 때 (3문제 90분 기준)
- 10분 룰: 한 문제 10분 봐도 패턴 안 잡히면 다음 문제로.
- 한 바퀴 다 돌고 → 만만한 거 먼저 완성 → 어려운 거 다시.
- 절대 한 문제에 30분 이상 박지 않음.
- 모든 문제 brute force라도 일단 다 제출 → 그 다음 최적화.

## 6. 자기 함정 회피 (학습_메타_노트의 갈래 빠짐 패턴)

오픽 학습에서 발견한 자기 함정 패턴이 코테에도 그대로 적용됨.

### ❌ 한 번에 최적해 노리지 마 → brute force부터
- 오픽에서 "한 번에 AL 답안" 노리다 갈팡질팡했던 것과 동일.
- 코테도 "한 번에 O(N) 해" 노리면 30분 날림.
- 일단 O(N^2) brute force → 통과되면 그대로 / 안 되면 최적화.

### ❌ 추상 라벨 만들지 마 → 정해진 패턴명만
- 오픽에서 "관찰형/감정형" 같은 자작 라벨 만들다 막힌 거랑 동일.
- 코테에서도 "이건 뭔가 새로운 알고리즘인가?" 의심하지 말 것.
- 99%는 기존 패턴 (DP/그래프/투포인터/해시/이진탐색/그리디) 중 하나.
- 새 패턴처럼 보이면 → 입력 변형해서 기존 패턴에 끼워 맞춰 봄.

### ❌ 자기 함정에 빠지면 잠깐 멈춤 (10분 brain dump)
- 같은 코드 30분 째 디버깅 중이면 → 멈춤.
- 종이에 문제 다시 적어보고, 손으로 예제 다시 풀어봄.
- 머리에서 안 나가는 잘못된 가정 찾기.
- 가장 흔한 잘못된 가정: "이 자료구조여야 함", "이 알고리즘이어야 함".

### ❌ "이 패턴인 것 같은데" 라고 우기지 마
- 손풀이 결과랑 가정한 패턴이 안 맞으면 → 패턴 가정이 틀린 것.
- 코드 고치지 말고 가정 갈아엎음.
- 손풀이 = 진실. 가정 = 의심해야 할 가설.

### ❌ 모범답안 보지 마 (시험 끝나고)
- 풀이 중에 검색은 당연히 X.
- 시험 끝나고도 모범답안 보기 전에 한 번 더 자력으로 시도.
- 모범답안 골격을 본인 손으로 재현할 때까지 양치기.

## 7. 시험장 루틴 (실전 모드)

### 시작 전 1분
- 화장실 다녀옴.
- 펜 + 종이 (손풀이용) 준비.
- 키보드 단축키 확인 (저장 / 실행 / 제출).
- 언어 환경 확인 (Python 버전, import 가능 라이브러리).

### 첫 문제 열자마자
1. 문제 끝까지 읽음 (제약조건, 입출력 형식까지).
2. N 범위 메모 (시간복잡도 한계 계산).
3. 예제 1~2개 종이에 손으로 풀어봄.
4. Section 1의 5단계 시작.

### 제출 직전 체크
- [ ] 입출력 형식 맞음 (줄바꿈, 공백, 인덱스)
- [ ] 엣지케이스 통과 (N=1, 빈 입력, 최대값)
- [ ] 변수명 오타 없음
- [ ] print 디버그 코드 제거
- [ ] 시간복잡도 N 범위 안에서 OK
- [ ] 입력 파싱 방식 맞음 (한 줄 vs 여러 줄, 공백 vs 줄바꿈)

## 8. 양치기 학습 루틴 (시험 전 일상)

오픽 양치기 = 같은 토픽 100번 변형해서 답안 골격 체화.
코테 양치기 = 같은 알고리즘 패턴 30~50문제 풀어서 골격 체화.

### 한 패턴당 양치기 절차
1. 대표 문제 1개 자력으로 풀어봄 (최대 1시간).
2. 모범답안 보고 골격 학습.
3. 골격을 종이에 적어봄 (외운 거 확인).
4. 비슷한 문제 5~10개 더 풀어봄 (입력만 변형된 거).
5. 손이 외울 때까지 반복.

### 추천 양치기 순서 (기초 → 응용)
1. 자료구조 (배열, 스택, 큐, 해시, 힙) — 10문제씩
2. 정렬 + 이진탐색 — 10문제
3. 투포인터 + 슬라이딩 윈도우 — 10문제
4. BFS / DFS — 15문제
5. DP 1차원 → 2차원 — 20문제
6. 다익스트라 / Union-Find / 위상정렬 — 각 5문제
7. 그리디 (양치기로 감각 익혀야 함) — 15문제

### 양치기 멈춤 신호
- 같은 패턴 5문제 연속 자력 풀이 성공 → 다음 패턴.
- 같은 패턴 3문제 연속 실패 → 골격 다시 외움 (4단계로 복귀).

## 10. 핵심 한 줄

> **모르는 문제 = 아는 패턴의 변형. 30초 안에 패턴 식별 못하면 brute force.**

오픽에서 "모르는 토픽도 카탈로그 변형으로 IH 뽑아냈다"는 자신감이
코테에서도 "모르는 문제도 패턴 변형으로 부분 점수는 뽑는다"로 이어짐.
